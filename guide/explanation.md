# 설명 규칙

무엇을, 어떤 순서와 문장으로 설명하는가. 화면에 들어가는 모든 글(header, 단계 카드, 툴팁, foot)에 적용한다.

## 독자

- 사용자 본인이다. 자율주행 데이터·HD맵·ML 을 다루는 엔지니어이고, 시간이 없다.
- 기초를 장황하게 풀지 않는다. 대신 용어는 처음 나올 때 **한 줄로 정의**한다.
- "쉽게"보다 **정확하게, 짧게**. 비유는 메커니즘을 틀리지 않게 옮길 때만 쓴다.

## 언어

- 문장은 한국어. 용어는 영어 원문 그대로 쓴다: `Kalman gain`, `junction`, `road block`, `bbox`. 억지로 번역하지 않는다.
- 코드 식별자·필드·파일 경로는 `<code>` 로 감싼다.
- 영어는 미국식 철자를 쓴다 (color, center, meter, neighbor, behavior, -ize).
- 화면에 실리는 **데이터 값**(원본 문자열, 디코드 라벨)은 번역하지 않고 원문 그대로 둔다. 원본과 대조할 수 있어야 한다.

## 구성 순서

페이지 전체가 보고서처럼 흐른다.

1. **h1**: 대상이 무엇을 하는지 쓴다. 질문형이나 "~란?" 은 쓰지 않는다.
   예) 「교차로 블록을 junction 으로 묶기」, 「route.json — what the planned route adds」
2. **3줄 요약 (`<ol class="sum">`)**: 문단 lede 를 쓰지 않는다. 문제 상황·핵심 규칙을 짧은 항목 3개로 쓰고(핵심 용어 굵게), 바로 그림이 보이게 한다. 조작 안내는 조작 패널 제목 옆 보조 설명으로, 좌표계·단위 같은 전제는 해당 패널 제목이나 foot 으로 보낸다 (2026-10-14 "첫 문단이 너무 길어. 아주 간단하게 문제 상황을 3줄 요약하고 바로 도식을 이해할 수 있도록").
3. **입력 → 규칙 → 절차(단계) → 결과** 순으로 단계 또는 절을 배치한다.
4. **foot**: 출처. 구현 `파일:줄`, 명세 문서, 논문 절·식 번호, 데이터 경로·버전, 주요 파라미터 값, 전체 규모 수치.

## 현재 로직만

- 지금의 규칙이 어떻게 동작하는지만 보여 준다.
- 이전 버전과 비교하는 톤, "문제" 단계, 이전 결과(점선 원·이전 id), 「1,580 → 1,252」 같은 전후 수치는 넣지 않는다.
- 사례가 규칙 변경 때문에 골라졌더라도 페이지 안에서는 현재 규칙의 예시로만 다룬다.
- 변경 경위는 명세서·블로그에 남긴다. 사용자가 비교를 요청하면 그때만 넣는다.

## 정답이 확정되지 않았으면 판정하지 않는다

- 정답 기준을 사용자가 확인해 주지 않았으면 정확도·비율, "맞다/틀리다", "개선" 을 쓰지 않는다.
- 두 규칙이나 결과를 비교해야 하면 **결과가 다른 사례만** 골라 각 출력, 근거 값, 관찰 사실을 나란히 놓는다. 판단은 사용자에게 남긴다.
- 대리 정답을 쓰고 싶으면 먼저 그 정의를 사용자에게 확인한다.

## 숫자

- 화면의 모든 수치는 스크립트로 계산한 값이다. 지어내거나 어림하지 않는다.
- 숫자와 단위 사이는 띄운다: `1.0 m`, `0.5 s`, `12 °`. 천 단위에는 콤마를 쓴다: `9,241`.
- 소수 자리는 의미가 있는 만큼만 쓴다. 표·stats 에는 `font-variant-numeric: tabular-nums` 를 적용한다.
- 파라미터는 실제 코드 값을 기본값으로 두고, 이름도 코드의 이름을 쓴다(`geom_margin_m`).

## 단계 카드 문장

- eyebrow `.k`: `STEP 2 · 공유 진입` 처럼 번호와 키워드를 쓴다.
- h2: 이 단계가 **하는 일** 한 줄을 쓴다.
- 본문 2–4문장: 무엇을 하는지 → 왜 하는지 → 기준값은 무엇인지. 한 문장에는 사실 하나만 담는다.
- stats: 이 단계의 결과 수치를 최대 3개까지 넣는다. 라벨은 짧게 쓴다.
- 범례: 이 단계에서 **내려지는 판정만** 넣고, 개수와 한 줄 설명을 단다 (`interaction.md`).

## 수식

- 필요할 때만 넣는다. KaTeX(classic) 로 그린다.
- 수식의 기호는 화면 요소와 연결한다. 기호에 hover 하면 해당 막대·점·선이 강조되고, 반대 방향도 마찬가지다.
- 수식 바로 아래에 각 기호를 한 줄씩 설명한다.

## 하지 않는 것

- 대화 Q&A 를 옮기지 않는다. 사용자의 질문은 페이지 주제가 아니다. 대상 자체를 설명한다.
- 이모지, 감탄, 마케팅 문구("강력한", "놀라운")를 쓰지 않는다.
- 같은 말을 header·카드·foot 에서 반복하지 않는다.
- 자리 채우기용 lorem 이나 가짜 데이터를 넣지 않는다.
