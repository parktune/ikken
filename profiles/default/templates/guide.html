example-cli 로
로그를 모아 보내는 방법

example-cli 는 여러 장비의 로그를 한 곳으로 모읍니다. 장비마다 수집기를 띄우고, 모은 파일을 정해진 주기로 저장소에 올립니다.

중앙 서버 없음전송은 SSHPython 3.11 이상
이 문서에서한눈에 보기처음 설치하기평소에 쓰기주의와 한계자주 쓰는 명령

한눈에 보기

각 장비의 수집기는 자기 로그만 다룹니다. 모으는 쪽이 SSH 로 장비에 들어가 파일을 가져옵니다.

구조 그림화살표 = 데이터가 가는 방향
장비 A수집기 · 로컬 버퍼
SSH 연결B 가 A 에 접속
A → B · 로그 전송B → A · 수신 확인
저장소 B날짜별 폴더

연결은 B 에서 시작합니다. A 에 열린 포트를 만들지 않습니다.

기억할 점: 수집기를 띄웠다고 바로 올라가지 않습니다. B 가 다음 주기에 접속해야 파일이 옮겨집니다.

처음 설치하기

전제: 두 장비 모두 Linux, Python 3.11 이상, B 에서 A 로 비대화형 SSH 접속이 됩니다.

1. 양쪽에 설치

git clone https://example.com/example-cli.git
cd example-cli
python3 -m venv .venv
.venv/bin/python -m pip install -e .

이후 예시의 example-cli 는 .venv/bin/example-cli 를 뜻합니다.

2. 장비 A 에서 수집기 시작

.venv/bin/example-cli collect --name device-a
한쪽만 접속하는 이유: B 가 A 에 접속할 때 로그를 가져오고 수신 확인도 함께 남깁니다.

평소에 쓰기

  1. A 에서 로그가 쌓입니다. 수집기가 버퍼 폴더에 시간순으로 씁니다.
  2. B 가 주기적으로 가져갑니다. 기본 5분마다 접속합니다.
  3. 실패하면 다음 주기에 다시 시도합니다. 같은 파일은 한 번만 저장됩니다.
A 에서 확인

example-cli status 로 버퍼에 남은 파일 수를 봅니다.

B 에서 확인

example-cli pulled --today 로 오늘 받은 파일을 봅니다.

주의와 한계

버퍼는 자동으로 지워지지 않습니다: 디스크가 차기 전에 prune 을 실행합니다.
  • 현재 Linux 만 지원합니다.
  • 파일 하나가 2 GB 를 넘으면 건너뜁니다.

자주 쓰는 명령

명령효과
collect --name NAME이 장비에서 수집기 시작
status버퍼에 남은 파일 수
pulled --today오늘 받은 파일 목록
prune전송이 끝난 버퍼 파일 정리
