# 상호작용 규칙

## 단계형 (알고리즘 진행, 재현 시뮬레이터)

- 단계 번호 버튼과 이전/다음은 **조작부(`.ctrl`) 한 덩어리**로 묶고, 그림·설명 카드와 다른 영역에 둔다.
  반복 클릭하는 조작부는 **어느 폭·레이아웃에서도**(넓은 2열, 한 열로 접힌 좁은 화면, Confluence embed) 단계를 넘길 때 화면 위치가 변하지 않아야 한다.
  - 길이·높이가 변하는 요소(그림, 설명 카드, 기록 표)를 조작부보다 앞(위)에 두지 않는다.
  - 넓은 2열: 오른쪽 열 맨 위. 한 열로 접히면 맨 위에 sticky. embed: 맨 위, 나머지 행 높이는 비율로 고정한다.
  - 이유: 조작부가 그림 아래에 붙으면 그림 높이에 따라 버튼이 오르내려 마우스를 고정한 채 연속 클릭할 수 없다 (2026-09-30 STRtree 설명 카드 길이; 2026-10-21 HD맵 속성 확장 — 좁은 폭에서 한 열로 접히자 그림 높이 변화가 버튼을 수십–수백 px 밀었다).
- 단계 번호 버튼은 mono 글꼴의 한 줄 grid 로 두고, 현재 단계는 반전(`aria-current="true"`) 한다.
- 단계가 **5개를 넘으면** 번호 버튼은 5개씩 페이지로 나눈다: `[‹ 페이지][번호 5칸][페이지 ›]`.
  - 이전/다음이나 키보드로 다른 페이지의 단계로 가면 번호 페이지도 따라 넘어간다.
  - 마지막 페이지의 빈칸도 자리를 지켜 버튼 위치가 변하지 않게 한다.
  - 이유: 번호 버튼이 한 줄에 10개 넘게 늘어서면 한눈에 보기 어렵다 (2026-10-21 13단계 페이지).
  - `templates/walkthrough.html` 의 `drawSteps()` 가 구현한다.
- 키보드: `←/→` 또는 `PageUp/PageDown` 으로 단계를 이동하고, `Home/End` 로 처음/끝으로 간다. 입력창에 포커스가 있을 때는 무시한다. 버튼 `title` 에 단축키를 적는다.
- 판정 범례는 **그 단계에서 실제로 내려지는 판정만** 보여 준다. 개수와 한 줄 설명을 붙인다.
  - 판정을 켜고 끄는 체크박스는 두지 않는다. 판정이 단계에서 나온다는 사실이 흐려진다.
  - 판정 범례에 색 견본(swatch)을 넣지 않는다. 그림은 레이어 색으로 그려져 범례 색과 맞지 않는다.
  - 판정이 없는 단계(경로 선택, 보정 등)에서는 범례 칸 자체를 숨긴다.
  - 마지막 결과 단계 범례는 "어느 단계에서 정해졌나" 기준으로 포함·제외 개수를 단계별로 나눈다.
- 레이어 토글은 그 단계에서 실제로 그려지는 레이어만 보여 준다. 아직 등장하지 않은 것(나중 단계에서 끌려오는 대상)은 앞 단계에 그리지 않는다.
- 요소를 **클릭하면 단계별 이력**을 보여 준다: 어느 단계에서 포함·제외됐는지와 그 이유, 그리고 속성.

## 지도·평면 (2D SVG/Canvas)

- 드래그는 pan, 휠은 커서 기준 zoom 이다. `cursor: grab`/`grabbing`, `touch-action: none` 을 준다.
- `Fit` 버튼을 둔다. 필요하면 `Follow`(대상 따라가기) 도 둔다. 움직이는 대상(ego)이 있는 작은 도식은 "대상 가까이"(따라가기, 기본) / "구간 전체" 두 버튼으로 충분하다.
- 실제 공간 데이터는 실제 단위의 scalebar 를 오른쪽 아래에 둔다. 축 비율은 1:1 로 유지한다.
- hover 하면 tooltip 에 id 와 핵심 값 2–3개를 mono 로 보여 준다. 클릭하면 사이드 패널에 상세가 나온다.
- 선택된 요소는 `--hit` 색으로 강조하고 나머지는 흐리게 한다. 선택 해제는 빈 곳 클릭이나 `Esc` 로 한다.

## 3D (three.js)

조작은 다음을 기본으로 한다. `templates/view3d.html` 에 구현돼 있다.

- **키보드**: `W/A/S/D` 는 카메라가 보는 방향 기준 xy 이동(앞/왼/뒤/오른), `Q` 는 아래, `E` 는 위로 움직인다. 누르고 있는 동안 연속으로 움직이고, 속도는 줌 거리에 비례한다.
- **Shift 홀드**: 이동 속도가 4배가 된다.
- **좌클릭 드래그 가로**: 장면이 마우스를 따라 돈다 — 오른쪽으로 끌면 장면이 오른쪽으로 돌고 카메라는 반대로 간다 (`theta -= dx`, three.js OrbitControls 와 같은 방향).
  - 이유: "카메라가 마우스를 따라" 도는 방향이었는데 사용자가 좌클릭 가로 드래그가 반대라고 했다 (2026-10-21 HD맵 속성 확장 3D).
- **좌클릭 드래그 세로**: 장면을 잡고 끄는 쪽이다. 마우스를 아래로 끌면 카메라가 올라가 내려다본다.
- **우클릭 드래그**: 장면을 잡고 끄는 pan 이다(마우스 오른쪽 → 장면도 오른쪽). Shift+드래그 pan 은 두지 않는다.
- 회전 중심(카메라가 바라보는 점)에 **x · y · z 축 선분**(빨강 · 초록 · 파랑, 토큰 `--ax-x/y/z`)을 항상 그린다. 화면에서 길이가 일정하고(줌 거리에 비례해 키움), 굵기가 보이게 가는 원기둥으로 그린다(Line 은 1 px). 다른 객체에 가리지 않게 오버레이 장면에 두고 본 장면 뒤에 깊이를 비우고 그린다. z 색은 장면의 다른 강조색(예: 보라)과 구분되게 고른다. 템플릿의 `placeFocus()` · `ovl` 이 구현한다.
  - 이유: 회전·이동할 때 어디를 중심으로 도는지, 축 방향이 어디인지 보이게 — "focus point도 조그맣게 하나 만들어", "점 말고 xyz 선분으로 표시해줘" (2026-10-21 HD맵 속성 확장 3D).
- 휠은 zoom, 더블클릭은 그 점으로 focus, `F` 는 전체 보기다. 조작법 한 줄을 뷰 왼쪽 아래에 muted 로 적는다.
- 세계 좌표는 z-up 이다. 지도 데이터는 원점을 대상 중심으로 옮겨 float 정밀도를 지킨다.

## 시간축 (프레임 데이터)

- player 를 이 순서로 둔다: `◀ ▶`(붙여서) → 재생 토글 → range → 프레임 라벨(mono). 줄이 바뀌어도 순서를 유지한다.
- 키보드: `←/→` 는 한 프레임, `Shift+←/→` 는 10 프레임, `Space` 는 재생/정지다.
- 현재 프레임 기준 값은 사이드의 key-value 표("At this frame")로 보여 준다.
- 시간축 막대(strip)는 행 하나가 한 방식(또는 한 신호)이고, 구간 색 = 그 프레임의 결과 개체다. 누르거나 끌면 그 프레임으로 가고, 굵은 세로선이 현재 프레임이다. 볼 사건 구간은 행 아래 짧은 검은 막대로 표시한다.
- **여러 방식을 비교하면 "방식 선택" segmented 를 둔다.** 고른 방식의 결과로 도식을 칠한다 — 궤적 점 = 프레임마다 그 방식의 결과 색, 현재 프레임의 결과 개체는 진하게 + id 라벨. 막대의 행 이름을 눌러도 고르고, 고른 행은 배경 · 굵은 글씨로, 시점 값 표의 그 줄도 굵게 표시한다.
  - 이유: 네 방식이 고른 차로를 한꺼번에 칠하니 구분이 안 됐다 — "사용한 매칭 로직에 따라 도로에서 어떤 lane에 매칭되는지 볼 수 있게" (2026-10-26).
- 한 페이지에 player 가 여러 개(사례 카드 목록)면 프레임 위치 · 재생은 카드마다 따로 움직이고, 키보드 `←/→` 는 마지막으로 만진 카드에 간다. 방식 선택 · 보기 범위는 카드끼리 공유한다(아래 「공통」).

## 파라미터 놀이터

- slider 와 현재 값(mono, 단위 포함)을 한 줄에 둔다. 기본값은 실제 코드 값이고 `reset` 버튼을 둔다.
- 값을 바꾸면 즉시 다시 그린다. 계산이 무거우면 싼 근사부터 즉시 보여 주고 정확한 값은 뒤따르게 한다.
- 손잡이를 돌렸을 때 **무엇이 바뀌어야 하는지** 한 줄로 적는다 (예: "R 을 키우면 gain 이 줄어 측정을 덜 믿는다").

## 조합 (combinator)

- 여러 조건이 엮이는 주제는 조건별 버튼 묶음으로 사용자가 조합하게 한다. 사례 번호 버튼(1–N)으로 대신하지 않는다 (2026-10-14). 레이아웃은 `patterns.md` 「combinator」.
- 조작 패널은 결과가 바뀌는 패널들 사이(또는 바로 옆)에 둔다. 한 조건이 의미 없으면(예: "회전 없음"일 때 회전 위치) 그 묶음을 비활성화한다.

## 공통

- **같은 모양의 패널이 여럿이면(사례 카드 · 탭), 모든 패널에 똑같이 적용되는 보기 옵션은 페이지에 하나의 상태로 둔다** — 방식 선택(지금 규칙 / 제안), 보기 범위(대상 가까이 / 구간 전체), 레이어 토글 같은 것. 한 패널에서 바꾸면 모든 패널의 버튼 눌림과 그림이 함께 바뀐다. 패널마다 다른 값(프레임 위치 · 재생 · 선택한 요소)만 패널 상태로 둔다. `templates/compare.html` 의 `VIEW` · `setView()` 가 구현한다.
  - 이유: 사례 1에서 Viterbi 를 눌러도 사례 2로 가면 다시 지금 규칙이라 비교할 때마다 다시 눌러야 했다 — "사례 1에서 Viterbi를 눌렀다면 다른 패널을 눌러도 Viterbi가 눌려있는 디자인 스타일이 내가 추구하는 방향" (2026-10-26).
- **이미지(사진 · 카메라 프레임 · 스크린샷)는 누르면 화면 전체로 크게 본다(lightbox).** 이미지 위에 겹친 오버레이(박스 · 투영 · 라벨)도 같은 좌표로 함께 키우고, 패널 제목을 캡션으로 단다. 바깥 · `×` 버튼 · `Esc` 로 닫는다. 열린 동안 사례 · 프레임을 넘기면 확대 화면도 따라 바뀐다. 이미지에는 `cursor: zoom-in` 과 `title` 을 준다. Confluence 임베드에서는 iframe 안을 덮는다. 컴포넌트 모양은 `style.md` 「lightbox」.
  - 이유: 작게 붙인 이미지로는 박스 정렬 같은 세부가 안 보였다 — "html에 이미지를 첨부할 때는 이미지를 클릭하면 화면에서 크게 보여주는 기능을 넣어줘" (2026-10-28, box_undist 정렬 점검).
- 테마 토글 버튼을 오른쪽 위에 둔다(`data-theme` 순환: auto → light → dark).
- 모든 아이콘 버튼에 `title` 과 `aria-label` 을 단다.
- 보이는 것만 클릭할 수 있게 한다. 겹친 요소가 클릭을 가로채지 않는지 확인한다(`verify.md`).
- URL hash 로 상태(단계·프레임·선택)를 남기면 공유하기 좋다. 필수는 아니다.
