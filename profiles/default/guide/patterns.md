# 페이지 유형

먼저 독자가 묻는 **이해의 축**(단계 · 카테고리 · 시간 · 공간 · 조건 조합)을 정하고, 그다음 유형을 고른다 (`SKILL.md` 3).
- 섞어도 된다(예: walkthrough 의 stage 안에 파라미터 slider). 맞는 유형이 없으면 새로 짠다. 아래 표는 출발점이지 틀이 아니다.
- 코드가 단계로 짜여 있다고 단계형을 고르지 않는다. 독자의 물음 단위가 화면의 단위다.
- 시간(또는 거리)을 따라 쌓인 데이터 — 프레임마다 붙는 라벨 · 판정이 대표적이다 — 는 규칙을 단계로 쪼개지 말고 **시간축(또는 거리축) 바**를 두고 넘기며, 각 시점의 값과 **왜 그 값인지**(그 시점에 적용된 규칙 · 근거 값)를 옆에 보여 준다. 축 단위는 프레임이 아니어도 된다(초 · 주행 거리). 규칙 표를 함께 두고 지금 적용된 줄을 강조한다. 플레이어 조작은 `interaction.md` 「시간축」.
  - 이유: command.driver 라벨을 5단계 walkthrough 로 그렸더니 "프레임바를 만들고 프레임이 지나감에 따라 각각이 왜 그렇게 레이블 되었는지 설명하는 방식이 더 적절", "시간이 관련된거면 시간의 흐름에 따라 시각화를 하는게 하나의 방법이야. 혹은 거리도 괜찮아" (2026-10-22).
- 골격이 있는 유형은 `templates/` 에 바로 열리는 파일이 있다.

| 유형 | 언제 | 골격 | 기존 예 |
|---|---|---|---|
| **walkthrough** 단계 따라가기 | 알고리즘·규칙이 순서대로 무언가를 판정·변형한다 | `templates/walkthrough.html` | 교차로 블록 묶기, STRtree 설명 |
| **explorer** 탐색기 | 실제 데이터(프레임·세션·레코드)를 넘겨 보며 패턴을 찾는다 | `templates/explorer.html` | 경로 JSON 탐색기 |
| **overview** 구조 개관 | 저장소·시스템·문서의 구성과 흐름을 한 번에 잡는다 | `templates/overview.html` | 저장소 개관 |
| **view3d** 3D 단계 뷰 | 높이·3D 기하가 본질이다 (고도, 센서 배치, 3D 맵 crop) | `templates/view3d.html` | 3D 맵 crop, 고도 보기 |
| **catalog** 카테고리 탐색 | 대상이 여러 종류(레이어 · 클래스 · 메시지 타입 · 모듈)로 나뉘고, "각 종류는 무엇으로 이루어지고 어디서 값을 받나" 가 궁금하다 | 골격 없음 — 아래 「catalog」 구성으로 짜고 공통 부품만 가져온다. 공간 객체면 3D 조작은 `view3d.html` 것을 그대로 | HD맵 레이어 속성 확장 |
| **combinator** 조합 놀이터 | 여러 조건(입력 A × 입력 B × …)이 엮여 결과가 갈린다 — 사례 목록보다 사용자가 직접 조합하는 편이 빠르다 | walkthrough 골격의 stage·패널 스타일을 쓰고 단계 버튼 대신 조작 패널 | 신호등 상태 조합 |

## walkthrough

- 왼쪽 **stage** 에 그림(SVG 기본, 요소가 수천 개를 넘으면 Canvas)을 두고, 오른쪽 380px 열 맨 위에 **ctrl**(단계 버튼 → 이전/다음), 그 아래 **side**(카드)를 둔다.
  - 셋은 grid 영역(`stage` · `ctrl` · `side`)으로 나눈다. 한 열로 접히면 `ctrl → stage → side` 순서이고 ctrl 은 sticky 다 (`interaction.md` 단계형).
  - 그림 패널을 여러 개 쌓는 페이지는 embed 에서 탭으로 바꾼다 (`confluence.md`).
- 단계 정의는 데이터로 둔다: `{key, title, body, stats, legend, vis}`. `vis` 는 그 단계에서 그릴 레이어·판정이다. 단계를 바꾸면 `render(step)` 하나로 stage 와 카드를 함께 갱신한다.
- 이론 주제는 "작은 실제 예" 하나를 끝까지 따라간다. 단계는 4–8개가 적당하다.
- 파라미터 놀이터는 카드 안 `.uf` 블록(slider + 값 + reset + 짧은 로그)으로 넣는다.

## explorer

- sticky header 에 제목, `.sub`(mono 메타: 데이터 출처·규모), controls(select, player)를 둔다.
- 본문은 카드 grid 다. 큰 그림 카드(Map 등)와 "At this frame" key-value 카드를 두고, 그 아래 full-width 카드에 요약 차트와 "이 데이터가 주는 것" 정리를 둔다.
- 카드 h2 에는 짧은 이름 + 작은 tag + muted hint(조작법) 를 넣는다.

## overview

- 980px 단일 열이다. h1 → lede → toc → 번호 매긴 h2 절(`1. 전체 흐름` …) 순서다.
- 흐름도는 `.flow` box + 화살표 grid 로 그리고, 좁은 화면에서는 세로로 바꾼다. 관계가 복잡하면 SVG + dagre 를 쓴다.
- 파일 구성은 `.files` 카드 grid 로, 절차는 번호 원(`ol.steps`) 으로 보여 준다. `.note`/`.warn` callout 은 꼭 필요할 때만 쓴다.
- 코드 저장소라면 상호작용을 하나 이상 넣는다: 흐름도 노드를 클릭하면 해당 파일·함수 설명이 열리고, 핵심 알고리즘은 작은 walkthrough 블록으로 보여 준다.

## view3d

- 전체 viewport 를 쓰고, `main` grid 는 `minmax(0,1fr) 380px` 다. `#view` 에 canvas, 왼쪽 위 HUD(전체·평면·높이 배율), 왼쪽 아래 조작법 한 줄을 둔다.
- aside 는 sticky nav(◀ ▶ + 단계명) → 설명 → 범례 → 레이어 → 목록 → 선택한 대상 순서다.
- 높이 배율 slider(×1–10)를 둔다. 고도 차가 작은 데이터는 과장해야 보인다.
- 조작 규칙은 `interaction.md` 「3D」 를 따른다. 골격에 구현돼 있으니 고치지 않는다.

## catalog

- 위 **카테고리 지도** — 종류가 실제 공간 객체(맵 레이어 · 센서 · 차량 부품 등)이면 **추상 그래프 대신 실제 장면**(3D 또는 지도)에 그 객체들을 실제 기하로 그린다.
  - 객체를 눌러 고른다. 고른 객체가 레코드 하나이고, 아래 상세가 그 레코드로 바뀐다.
  - 관계는 장면에서 보여 준다. 고른 객체와 id 로 이어진 객체를 강조하고 선으로 잇는다: 가리키는 쪽은 실선, 가리켜지는 쪽은 점선. 나머지는 흐리게 하되 맥락이 읽히는 정도(불투명도 0.4 안팎)로 둔다.
  - 층으로 쌓인 구조면 "레이어 띄우기" 슬라이더로 층을 높이별로 벌리고 층 이름을 단다.
  - 옆에 종류 목록을 두고 보이기 토글 · 장면 객체 수 · 구성 막대(예: 필드 출처 비율)를 넣는다. 목록을 누르면 그 종류의 대표 객체로 이동한다. 장면에 없는 종류는 장면 밖 예시 레코드로 상세를 보여 준다.
  - 이유: 레이어 관계를 노드 그래프로 그렸더니 직관적이지 않았다 — "실제로 hdmap 의 구조와 유사하게 3d 화면이 있고, 클릭해가면서 어떻게 구성되는지 볼 수 있게" (2026-10-21).
- 공간이 없는 종류(메시지 타입 · 모듈 등)는 노드 그래프(값의 흐름 · id 참조 선, 들어오는/나가는 선을 다른 색으로)나 타일 grid 로 둔다. 좁은 화면(≤640)에서는 그래프를 타일로 바꾼다.
- 아래 **고른 종류의 상세**: 입력 → 출력 매핑을 실제 레코드 하나로 보여 준다(왼쪽 원본 키 · 오른쪽 결과 필드 · 둘을 잇는 선).
  - 결과 항목은 출처 갈래별로 묶고 갈래마다 색과 개수를 단다.
  - 옮기지 않는 원본 키와 원본에 없는 키도 숨기지 않고 표시한다.
- 오른쪽 **항목 상세**: 고른 항목의 규칙 · 출처 · 채워진 비율 · 예시 값을 보여 준다. 다른 종류를 가리키는 출처는 눌러서 그 종류로 이동한다.
- 단계 정보가 있으면 항목 상세의 속성(예: "expand 단계 4")으로 붙인다. 화면의 주 조작은 카테고리 선택이다.

## combinator

- 고정 사례 1–N 을 나열하지 않는다. 조건마다 segmented 버튼 묶음을 두고, 고르는 즉시 그림 · 결과 · 설명이 바뀐다 (2026-10-14 "1번부터 7번 샘플을 두는게 아니라 사용자가 조합할 수 있게").
- 배치는 한 줄 **[그림 패널 | 조작 패널 | 결과 패널]** — 조작 패널을 그림과 결과 사이에 둬서 조작하며 양쪽을 함께 본다. 그 아래 줄은 설명 패널(행 전체, 안을 여러 칸으로).
- **결과 패널**은 주제에서 가장 중요한 값(예: 두 status 와 그 관계)만 크게 보여 준다. 입력 → 중간 판단 → 결과 순으로 세로로 쌓는다 (2026-10-14 "Detector 와 E2E 의 두 값이 제일 중요해 … 바로 볼 수 있게").
- 표(조건 × 조건 → 결과)를 함께 두면 칸 클릭으로 조합을 바꾸고, 지금 조합 칸을 테두리로 표시한다.
- 실제 사례가 있는 조합은 그 값과 사진을, 없는 조합은 "도식 값" 으로 표시한다.

## 데이터 싣기

- 데이터는 `<script type="application/json" id="data">…</script>` 에 넣고 골격의 `loadData('data')` 로 읽는다.
  Confluence 변환 때 이 블록이 gzip+base64 로 바뀌어도 `loadData` 가 그대로 읽는다.
- 좌표는 의미 있는 정밀도로 반올림한다(지도 0.1 m). 원점은 대상 중심으로 옮긴다.
- 파일이 수 MB 를 넘으면 샘플을 줄이는 기준을 구성안에 적는다.
